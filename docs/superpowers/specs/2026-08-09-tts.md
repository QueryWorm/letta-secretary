# TTS (text-to-speech) — Дизайн

**Дата:** 2026-08-09
**Статус:** draft (на одобрении)
**Объём:** MVP — озвучка ответов по триггер-словам

## Цель

Когда пользователь пишет в WhatsApp/Telegram слова-триггеры («скажи», «расскажи», «озвучь», «прочитай», «голосом», «voice»), Маша отвечает **только голосовым сообщением** (без текста), озвученным через edge-tts (Microsoft Edge, бесплатно, без ключа).

В остальных случаях — обычный текстовый ответ, как сейчас. Дополнительно — логирование времени по этапам pipeline для observability.

## Зачем

Сейчас Маша отвечает только текстом. Голосовые сообщения — естественный способ общения в мессенджерах (hands-free, в движении). Автоплей в Telegram/WhatsApp невозможен на уровне бота (UX-нормально — как голосовые в обычных чатах).

Логирование времени — чтобы понимать ботлнеки pipeline: где бот проводит время (LLM, TTS, отправка).

## UX-ограничения

- **Автоплей голосовых невозможен** без OS-level integration (Accessibility Services на Android, или десктоп). Это ограничение мессенджеров, не наш выбор.
- Пользователь **нажимает play** на voice note. Нормальный паттерн.

## Архитектура

```
User: "Маша, скажи погоду"
  ↓
Agent (persona rule):
  - триггер-слово "скажи" → отвечать ТОЛЬКО голосом
  ↓
Tool call: speak_text(text="Сейчас +27, солнечно")
  ↓
HTTP POST tts:8000/synthesize {"text": "...", "voice": "ru-RU-SvetlanaNeural"}
  ↓
Sidecar (Python + edge-tts):
  - generate .ogg (Opus codec, mono, 16kHz)
  - return audio_base64, duration_sec, synthesis_ms
  ↓
Tool returns: {"audio_base64": "...", "filename": "response.ogg", "duration_sec": 3, "tts_ms": 2300}
  ↓
Agent вызывает MessageChannel с audio attachment
  ↓
Channel adapter отправляет voice note (WhatsApp: .ogg/Opus, Telegram: .ogg/Opus)
```

## Подход

**Sidecar (Python + edge-tts)** + custom tool `speak_text` + persona rule.

Почему sidecar:
- `edge-tts` — Python-библиотека, не Node (бандл letta-code-channels — Node)
- Single responsibility: sidecar делает TTS, agent отправляет, persona триггерит
- Тестируемо: каждый компонент независимо
- Не нужно патчить бандл

## Компоненты

### 1. `tts/Dockerfile` + `tts/app.py` + `tts/requirements.txt` (новый sidecar)

- **Dockerfile**: `python:3.12-slim`, установить `edge-tts`, `fastapi`, `uvicorn`, `ffmpeg`
- **app.py**: FastAPI-сервер с тремя эндпоинтами
  - `POST /synthesize` — `{text, voice}` → `{audio_base64, filename, duration_sec, synthesis_ms}`
    - `voice` опционально, default `ru-RU-SvetlanaNeural` (Microsoft Svetlana, женский, выразительный)
    - Max text length: 5000 chars (обрезаем с warning в JSON)
    - Генерирует .ogg (Opus, mono, 16kHz) через edge-tts + конвертация в ogg через ffmpeg (если нужно)
    - Кеш: in-memory LRU 50 entries по хешу текста
    - **Timing**: замер `time.monotonic()` от старта до конца генерации → `synthesis_ms`
  - `GET /health` — для docker healthcheck
  - `GET /voices` — список доступных голосов (для отладки)
- **requirements.txt**: `edge-tts>=6.1`, `fastapi>=0.110`, `uvicorn[standard]>=0.27`

### 3. Custom tool агента `speak_text`

- **Имя**: `speak_text`
- **Описание**: «Озвучить текст через TTS (edge-tts). Используй когда Игорь просит голосом: слова "скажи", "расскажи", "озвучь", "прочитай", "голосом", "voice". Возвращает аудио-файл (.ogg), который будет отправлен как голосовое сообщение. БЕЗ отправки текста в этом случае.»
- **Параметры**: `{text: string, voice?: string}`
- **Source code (Python)**:
  ```python
  def speak_text(text: str, voice: str = "ru-RU-SvetlanaNeural") -> str:
      """Синтезировать речь через edge-tts sidecar. Возвращает JSON с base64 и timing."""
      import os
      import requests
      import base64
      import json
      import time
      base_url = os.environ.get("TTS_BASE_URL", "http://tts:8000")
      t_start = time.monotonic()
      try:
          resp = requests.post(
              f"{base_url}/synthesize",
              json={"text": text, "voice": voice},
              timeout=60,
          )
          resp.raise_for_status()
          data = resp.json()
          t_end = time.monotonic()
          tool_ms = int((t_end - t_start) * 1000)
          return json.dumps({
              "audio_base64": data["audio_base64"],
              "filename": data["filename"],
              "duration_sec": data["duration_sec"],
              "synthesis_ms": data.get("synthesis_ms", tool_ms),
              "tool_total_ms": tool_ms,
          })
      except requests.exceptions.RequestException as e:
          return json.dumps({"error": f"TTS unavailable: {e}"})
  ```

### 4. Persona правило

PATCH `core-memory/blocks/persona` — добавить новое правило:

> «Когда в сообщении Игоря есть слова "скажи", "расскажи", "озвучь", "прочитай", "голосом", "voice" — отвечай ТОЛЬКО голосовым: вызови `speak_text(text=...)` и отправь результат как voice message через `MessageChannel` с mediaPath. НЕ отправляй текст в этом случае. Иначе — обычный текстовый ответ как раньше. В конце КАЖДОГО текстового (НЕ голосового) ответа добавляй блок (после пустой строки): `[debug: llm=X.Xs]` — приблизительная оценка времени LLM-ответа в секундах. Считай примерно, не точно. Для голосовых ответов debug-блок НЕ добавляй.»

### 5. Channel adapter — поддержка audio

`MessageChannel` в бандле уже имеет `mediaPath` параметр. WhatsApp и Telegram адаптеры должны корректно отправлять .ogg как voice message. **Проверить в implementation task** — если не работает, добавить в план отдельной задачей.

### 6. Расширение существующего патча `patch-debug-tagging.py`

Текущий патч добавляет `[secretary-model | X.Ys]` в конец. **Оставляем** как есть, не трогаем (он даёт основной debug-инфо). LLM-время придёт из persona (агент сам оценит).

  ↓

  ↓

## Error handling

- **Sidecar недоступен**: tool возвращает `{"error": "TTS unavailable: ..."}` → agent отвечает текстом «Озвучка временно недоступна, вот текстом: ...»
- **Text > 5000 chars**: sidecar обрезает до 5000, возвращает warning в JSON
- **edge-tts вернул пустой файл**: retry 1 раз, потом error
- **WhatsApp/Telegram не поддерживает .ogg как voice**: tool всё равно работает, message приходит как document — пользователь увидит (acceptable)

## Тестирование

- **Sidecar unit**: `curl POST /synthesize` → 200 + base64 .ogg + synthesis_ms
- **Sidecar unit**: text > 5000 → truncation в warning
- **Sidecar health**: `curl /health` → 200
- **Agent end-to-end**: «Маша, скажи привет» → voice в WhatsApp
- **Negative**: «Маша, сколько времени?» (без триггера) → текст + debug `[llm=X.Xs]`
- **Timing log**: при текстовом ответе debug-блок присутствует; при голосовом — отсутствует

## Логирование времени (pipeline observability)

К каждому **текстовому** ответу пользователю добавлять debug-блок с замером LLM-времени:

```
[debug: llm=2.4s]
```

Реализация — через **persona правило** (агент сам пишет, не требует бандл-патча). Агент оценивает своё время ответа неточно — это OK для грубой observability.

Для более точных замеров (в перспективе) — расширить `patch-debug-tagging.py` чтобы вытаскивать timing из `lastInboundTs` (уже есть в бандле) + `Date.now()` при `buildMessageChannelRequest`. Сейчас не делаем, в MVP — persona-based.

## Что НЕ входит в MVP

- Streaming TTS (генерация пока говорит) — edge-tts не поддерживает стрим
- Мульти-голос (несколько голосов на выбор) — в MVP один голос
- TTS для cron-напоминаний — не сейчас
- Настройка голоса через persona — в MVP голос захардкожен
- Кеш на стороне агента — кеш только в sidecar
- Точное время LLM из бандла — persona-based оценка достаточно для MVP
- Voice для cron (TTS-напоминания голосом) — отдельная фича на потом
